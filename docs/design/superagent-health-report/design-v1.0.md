# Superagent 定期健康报告 — 合并设计 v1.0

日期：2026-11-11。性质：实施方案；尚未部署或开启推送。
根任务：health-db09dbce-8aef-4c35-acd6-d479d3270c3c。
目标：定期向管理人汇报心跳、实际模型、今日会话情况、一句话摘要、未完成与人工裁决项；在数据可信时附模型用量。
依据：[初稿](<D:/src/dsh/docs/design/superagent-health-report/draft-v0.1.md>)、[源码与实测证据](<D:/src/dsh/docs/design/superagent-health-report/evidence.md>)。已完成 Opus 5 与 Kimi K3 独立挑战，主控核验并合并；逐项处理见[挑战裁决记录](<D:/src/dsh/docs/design/superagent-health-report/review-decisions.md>)。

## 1. 定案

新增一个**独立于 Superagent 会话生命周期的轻量 reporter 服务**。它定时采集现有接口、生成确定性摘要、持久化待发送消息，再通过既有飞书通道发给指定管理人。心跳和计数不调用模型；不让 Superagent 自己靠提示词记住“每两小时报平安”。默认单机部署，可选异机监视服务判断整机失联。

首版覆盖六项必需内容；dashboard 用量是独立可降级模块。当前 dashboard 0.2.1 **不能直接承诺 Superagent 总消耗**：扫描发现器排除了已实际存在的 worker- 会话目录，查询也缺任意会话集合筛选。首版最多展示“dashboard 当前扫描集合用量（不含被排除的 worker 会话；其他遗漏未知）”；无法授权或不新鲜则显示不可用。精准专属用量进入第二阶段。

推荐管理通道为飞书，与已有集成一致；具体管理人、bot 身份、实例清单和时间表由设备配置提供。部署前核验绑定，设计阶段不猜收件人、不发送测试消息。

## 2. 组件与边界

配置实例 → 只读采集器 → 规范化快照 → 报告/告警规则 → SQLite outbox → 飞书适配器 → 管理人

- **采集器**：每个实例读 state、分页工单和会话观测元数据；各来源独立超时。优先公共接口，缺字段才使用版本锁定的宿主导出适配器。禁止读取凭据值或把聊天全文发到外部。
- **快照与规则**：保留来源时间、证据ID、状态映射、统计窗口与质量标记；状态来自权威源，不由自然语言猜测。业务工单状态和会话运行状态分开。
- **renderer**：首屏最多五行；详细页/消息分段包含每个会话的状态与recap。无授权的远端详情服务时，不发无法访问的本地路径作为唯一说明。
- **投递器**：独立消费outbox，失败不阻塞采样。反馈messageId是“渠道接受”，不是“管理人已读”。
- **任务计划/服务守护**：启动reporter、异常退出重启、保证单实例；本机可看reporter心跳文件。异机dead-man检查是可选部署，不和reporter共故障域。

首版显示层分为“服务状态、工作进展、需要管理人处理”三组；内部保留service/orchestrator/workers/sources/delivery/reporter/usageQuality七维证据，避免简化界面时丢失故障原因。

## 3. 默认节奏

时区默认 Asia/Shanghai；使用固定reportTimezone，禁止默默跟着设备变更。以下为可调整的推荐默认值，不代表已经启用。

| 任务 | 频率 | 行为 |
|---|---|---|
| 接口可达探测 | 60秒 | 每实例一个GET state；5秒超时；三次连续网络失败后一个故障episode，连续两次成功后一次恢复 |
| 工单/人工事项/会话增量 | 60秒 | 有增量契约则用增量；否则分页有界扫描，优先重查已知未完成项；大集合允许最长5分钟完整轮转并展示覆盖水位 |
| 全量未完成对账 | 每15分钟及发摘要前 | 分页读取，不能只读今天创建的工单；预算超限时标partial，不声称全量 |
| 工作时段摘要 | 09:00、11:00、13:00、15:00、17:00、19:00 | 不变也发送短平安摘要，以便用户观察推送链路仍在工作 |
| 日报快照 | 21:05 | “今日截至21:05，未闭账”；列今日活动与所有未完成 |
| 自然日闭账 | 次日00:10生成 | 窗口为前日[00:00,次日00:00)，静默期不推；次日09:00合并前日闭账及差异，无变化不另发一份 |
| 新人工事项/严重错误 | 下一次成功采集后60秒合并 | 同episode只发一次；人工事项发送成功30分钟后提醒，再每2小时，最多3次/工作日，之后入摘要 |
| 静默期 | 22:00–08:00 | 普通报告、提醒排队；严重服务中断绕过，可配置维护窗口 |

提醒计时从首次渠道接受后开始；失败重试是同一消息的传输行为，不生成新的提醒。首次启动仅历史终态做基线；**当前未完成/待人工项要出启动摘要**，不能随历史基线吞掉。恢复后汇总错过的普通周期，不连发所有旧平安消息。

## 4. 心跳与健康判定

明确三种时间：reporter采样完成时间、HTTP探测成功时间、业务进度时间。现有health.at是状态更新时间，不能拿它判心跳超时。

- HTTP 200仅证明接口可达。认证401/403是采集权限异常，不能归类“服务宕机”；schema不兼容也是采集异常。
- state内关键业务组件error则“在线但降级”；按组件和错误码建episode，变化时告警，不把每次error都当新事故。
- paused、sourceOff、localMode只在与预期配置不一致时告警；否则显示“已暂停/按配置关闭”。
- 调度循环没有可验证tick时写“调度循环活性未验证”。工单updatedAt说明有事件，不证明每个内部循环健康；无业务工作时无进度是正常。
- 有执行中任务且超过任务特定进度阈值，先显示“疑似停滞”，查工具/job运行、排队、模型退避证据；不自动终止、不把其改成业务failed。
- 本轮真实只读实测：3082/3083均可达；3082的reply/history出现error，说明“接口通=绿灯”会误导。故障信息仅作本轮证据，不能当未来持续状态。
- reporter进程崩溃/整机断电时不能自报。首版明确“无异机失联保证”；需要该保证时再上线独立watchdog，按独立60秒心跳和约5分钟缺失门槛告警，而不是用2小时摘要推断。

## 5. 今日会话与状态口径

报告同时保留三套计数，不能混加：**业务工单数、今日活动会话数、全部未完成存量**。今日活动=窗口内有执行事件的唯一会话（主控/执行worker/其子代理分别列出）；跨日会话可在不同日期的活动集合各出现一次，这不是重复计费。今日新建另列；只有createdAt不能证明今日被处理。

标识：工单键(instanceId,ticketId)；会话稳定身份(storageNamespace,sessionId)，实例关联另表；一个会话被多个实例引用时全局只计一次，实例视图不可直接相加。assignment是尝试，不另计业务完成。优先使用工单视图的sessionId，不把assignmentId硬当sessionId；无链接标unlinked。

| 权威来源（按上游优先级） | 报告业务状态 | 人工事项 |
|---|---|---|
| ended.completed / ended.merged | 已完成 | 不因旧ready报告自动复活 |
| ended.stopped | 已停止 | 显示原因，不算成功 |
| ended.closed / ended.dropped | 已结束未完成／不适用 | 原因保留，不强映射成成功或failed |
| person.delivery | 待人工处理：投递问题 | 附错误、恢复入口 |
| person.answer / attention | 待人工回答 | 问题来自attention.question |
| person.review / report.ready | 待人工验收 | 结果已就绪，但不计已完成 |
| person.blocked / person.failed | 待人工处理：阻塞/失败 | 保留技术失败原因；不能只放终态失败数 |
| working.queued | 排队 | 无 |
| working | 执行中 | 有明确外部等待证据时附waitReason |
| idle | 空闲但未结束 | 无新裁决证据不自动催人 |
| 无法映射/来源不可用 | 未知 | 显示数据缺口，不置零 |

会话栏展示运行状态和关联工单结果，不把一个主控会话涉及的多个工单折成“该会话完成”。初稿示例的“8个会话=4完成+…”改为分别列工单结果和活动会话数。停止一轮、进程退出、worker inactive不等于任务完成。

人工事项每次快照重算：stableIssueId=instance+ticket+attentionId（若无则原因类型+原始报告eventId），revision随证据更新。收到普通输入不意味着裁决已解决；只有权威状态清除attention/不再person，或显式独立裁决记录已解决才关闭；采集失败不关闭。终态工单的历史ready不生成待办。若有**独立且仍未关闭**的人工裁决记录，作为独立事项展示并提示与工单终态矛盾，不改写工单。

## 6. 当前模型和一句话recap

模型记录：configured、latestAttempt、inFlight、lastSuccessful分别保存provider/model/effort/observedAt/sourceEventId。报告“当前”优先展示有证据的inFlight，否则写“最近一次成功”；无成功则展示最近尝试及失败状态，无任何观测则未知。主控/worker/router分列；多worker按模型分组，保留数量及最老观测时间。配置仅标配置，不能替代实测。

观测入口：宿主session元数据modelSelection.lastUsed可辅助证明最近选择；实际请求header/context与assistant/message.source及usage用于验证请求/响应。若返回模型与请求别名不同，分别记录；fallback原因只有有事件证据时才显示，不能从两模型不同自行推断。effort缺失写未知。具体宿主字段、返回模型语义和事件时序须P0契约测试；reporter无需高频解压全会话。

每会话recap默认复用最新结构化report.summary / 已有one-line recap，并保留sourceEventId、生成时间及“截至哪一回合”。状态变化后旧摘要必须标旧，不能冒充当前。无可靠摘要显示**“暂无可用摘要”**，不从标题编造正在处理/已完成。可选未来LLM压缩只读已脱敏字段，有预算且失败回退；不进入首版关键链路。

人工事项卡：问题、来源、选项（已有则列）、影响、负责人、期限（未知则标未设置）、原操作入口；没有源数据时不编造建议。首版为通知+原入口处理，不接受聊天“好/同意”直接执行操作。当前会话的approval=never不会消除业务系统仍需人的裁决。

## 7. dashboard用量：能做什么、不能做什么

核查版本0.2.1。现有GET status/cube/pricing可以复用；cube同日查询用from=to=日期、groupBy=model、granularity=day、scope=all。summary不能替代指定日期查询。date桶是宿主本地日，启动必须核对其时区与reportTimezone；不一致时不可用，不能通过改日期字符串假装已换时区。

**三个独立质量维度**：freshness=fresh/stale/unavailable；coverage=complete-for-declared-set/partial/unknown；pricing=complete/partial/unknown。lastScanAt只是扫描结束时间，不能单独证明每个文件都成功；scanErrors、storage模式、截断及目录覆盖必须一起检查。

当前能力边界：

1. 扫描器只发现session-目录，磁盘已确认worker-会话目录存在，故这些worker目录被排除。卡片必须写“dashboard扫描集合；不含worker会话”，不能写“全部DSH”或“Superagent总消耗”。主控/外部ACP等其他未覆盖部分仍需核查。
2. cube支持project过滤但不支持任意session集合；sessions最多200条且无offset。不能用同目录近似归因，不能用截断列表求总和。
3. host只有启动scan与显式POST scan入口，未发现无人值守周期刷新。基础报告不依赖它；**启用用量模块**时需先验证受支持认证和后台刷新能力：独立维护任务每15分钟触发一次增量scan（full=false），已有扫描返回409则复用其完成结果；对扫描耗时、资源、超时设预算。日报前确保最近一次成功刷新。该POST会更新分析缓存，属于实施阶段单独启用的分析维护能力，不是本轮实际执行，也不是只读采集器偷偷写入。无法安全启用则明确stale/unavailable，绝不长期以旧值冒充今日值。
4. 15分钟是新鲜度阈值，不是自动刷新的保证。超过阈值只可显示“上次观测，截至某时”；过期数不计当前日预算告警。日报为版本化快照，次日闭账若扫描未完整仍标暂定，并可随后更正。
5. token显示input/output/cacheRead/cacheWrite及插件合计口径；先验标准化usage字段是否互斥，再使用合计，禁止无条件重复相加cache。无usage与真实0分开，保留msgsNoUsage/覆盖量（若源支持）；没有分母不编造百分比。
6. 成本为“配置单价估算”，币种与单价版本有证据才列；价格缺失时显示已定价小计+未定价模型，不能把dashboard回退0解释成免费。父子仅合计原子请求，不再加父层累计总额。ACP未回传usage标未知；无法证明无重复则不声称全量精确。

第二阶段“Superagent专属用量”需两个能力同时成立：扫描覆盖master/worker/child全部实际会话ID与存储根；提供session集合过滤或完整可分页事实导出。归因集合来自实例masterIds、ticket视图sessionId、子会话父子关系，不能按前缀推断全部归属。缺任何一项就不展示专属总额。

## 8. 投递协议与故障处理

本地SQLite使用事务保存快照、outbox和告警episode。普通key包含instanceSet+recipientBinding+type+window+revision，告警key包含incidentId+transition，提醒key包含issueId+reminderOrdinal。多实例并发由唯一约束和有期限发送租约控制；单实例锁不能替代数据库幂等。

状态：pending → sending(lease) → channel_accepted；明确失败→retry_wait；超时/崩溃后结果未知→unknown_delivery；达到预算或永久权限错误→needs_attention。channel_accepted不叫已读。失败重试使用同一idempotency key；只有验证渠道支持幂等才声称去重。可查询远端messageId/幂等键则先对账；无查询能力时按已配置策略有限重发，同reportId便于识别，**允许重复但不静默丢失，不承诺exactly-once**。

采集5秒超时与发送超时分开配置；建议发送30秒，退避30秒/2分钟/10分钟/30分钟，加抖动并尊重Retry-After。6小时未恢复则本地needs_attention及已配置备用通道告警；持久队列保留，不悄悄标已发送。关键待裁决项和严重故障不被普通摘要替代；过期平安摘要可superseded，需留审计记录。

首版保留outbox、单实例锁、去重和恢复；不能为了少代码退回“发送失败只写日志”。同一坏通道不保证发出它自身的故障告警。部分来源失败仍发报告，旧数据带时间和stale；数字未知用“未知”，不填0。

## 9. 管理人收到的内容（以下仅示意）

> Superagent · 21:05日报快照（未闭账）
> 服务在线；回复投递异常。最近探测21:04:58。
> 今日工单完成4项、待验收1项；活动会话8个。累计未完成3项。
> 需要你处理：发布范围确认1项；详见下一条事项卡。
> 摘要：接口联调已完成，发布范围仍待确认。（来源：最新工单报告）

紧接一条详情消息：主控最近成功模型provider/model与时间；worker模型分布；每个今日会话的短ID、状态、recap；未完成跨日项；数据缺口；可选用量。前10项优先异常与待人工，其余分页，每页附同reportId、页码和总数。详情链接仅在管理人实际能访问且经过授权时出现。

示意用量文案：“dashboard扫描集合：输入X、输出Y；worker会话未覆盖；已定价小计Z（配置币种）；截至21:00。非Superagent总账。”未接通则：“今日用量暂不可用：认证/刷新/覆盖条件尚未满足。”不输出虚构数字。

## 10. 实施门槛、验收与迁移

**P0，先验证数据契约**：确定实例/profile/版本/端点/存储命名空间，管理人绑定、时区、宿主只读授权，建立脱敏fixtures。会话实际事件和工单映射缺失则必须补适配器，不能拿工单数冒充会话数。新适配器和新增字段都必须版本协商，未知版本默认降级。

**P1，核心报告**：实现采集/规范化/模板/outbox/服务守护，先dry-run；输出完整报告而不发消息。下面场景均需可重复验证：

| 场景 | 必须结果 |
|---|---|
| 200但reply error；正常idle/sourceOff | 前者在线降级；后者不报宕机 |
| 401/403、schema漂移、部分分页失败 | 采集异常/partial，不能当无会话或健康 |
| ready、blocked、ended+历史ready、未知outcome | 映射符合第5节；终态不因历史记录复活 |
| 跨午夜/21:05后工作/跨日无新事件未完成 | 自然日活动准确；存量持续保留；闭账差异明确 |
| 配置A、尝试B失败、成功C；无模型/无recap | 分列尝试和成功；未知不猜测 |
| 发成功后本地ack前崩溃、429、30秒超时、双实例 | pending不会丢；幂等支持时不重复，不支持时重复有相同reportId可识别 |
| 权威人工事项已解决、采集暂不可用 | 成功采集后关闭；失联期间不擅自关闭 |
| reporter被杀、整机离线 | 本机守护恢复前者；后者明确仅异机watchdog能检测 |

**P2，用量模块**：通过带授权的status/cube/pricing读取、扫描维护、两天不重启新鲜度检查、价格与缓存口径、父子/ACP覆盖、worker目录和session集合完整性测试。仅扫描集合用量可以先启用，但必须醒目显示缺口；专属用量门槛独立。

**P3，可选**：异机watchdog、第二通知通道、带身份与revision校验的交互裁决，不纳入P1。
