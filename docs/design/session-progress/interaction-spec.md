# 交互稿制作边界

问题：用户能否在30秒内识别当前需决定事项，沿同一目标从L1到L3并返回，而不读完整会话？

- 单文件、无外部资源、合成数据、无持久化、不开服务器。模拟工作台侧栏+目标容器的上下文；不是往当前GUI注入页面，不受工作台兼容门禁影响。
- 三稿：A依赖检视（DAG）；B日常处理（看板+层级列表，建议默认）；C推进叙事（多轨汇合，不按真实时间比例）。
- 三稿共享view state：focus父任务、selected任务、filter、面包屑；切换保留焦点。支持URL ?variant=A/B/C。
- 点击节点只选中查看解释/证据；明确“下钻”按钮进入孩子；L3叶子显示已到底，可一键上钻；面包屑直达祖先。
- 任务状态与证据新鲜度分开；待决定/外部等待/上游依赖分开说明；叶子已完不自动验收目标。
- 看板只读无拖拽。列表展开与焦点下钻区分；表内父行进度是直接子项计数，不叠加子孙。
- DAG保留硬边；轨道只展示推进主线，隐藏依赖明确计数并可切换DAG；不把线的相邻关系伪装为依赖。
- 合成的“执行者/session/证据”均标明演示，不接真实日志。
