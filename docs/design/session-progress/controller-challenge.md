# 6.1 Sol 主控独立挑战（设计前约束）

1. **根目标不等于一个会话**：同一session多目标、同目标多session；必须用任务/目标稳定ID，session是来源的多对多引用。
2. **层级不等于依赖**：parent只表归属；depends_on单独存边，折叠后边聚合需保留底层endpoint，不能把分组误作全体等待。
3. **进度不能伪精确**：业务验收门数为主；子任务完成计数不能自动推出父目标已验收，不用LLM猜百分比/ETA。
4. **目标/技术是语义角色**：“让用户能登录”是结果，“改OAuth回调”通常为手段；若验收就是“OAuth回调漏洞消除”，技术就是结果。用outcome/enabler属性而非黑名单隐藏术语。
5. **地铁图不是任意DAG的无交叉排版器**：只绘制主推进线和门；存在非局部/非平面依赖时显示“另有N依赖”，DAG保全真实边，不用虚构转乘站掩盖依赖。
6. **三视图不是三个事实库**：同一snapshot、同一焦点、同一选中任务、统一更新时间；禁止看板拖拽直接改验收态。
7. **监控器不当裁判**：日志是提议/证据，不因“完成”措辞或子代理退出0而销项；同一来源更新按版本水位消费，过期与冲突均显示不覆盖。
8. **认知预算要硬**：每屏≤12个主节点、≤4轨、≤3条决策；完成支线默认摘要，焦点以外留出口计数，不能静默遗漏阻塞。
9. **增量粒度要现实**：现有extract是整文件zstd解压+截断digest，不承诺按压缩字节offset尾随；monitor可按已解码event id/seq去重，先低频变更文件批处理。
10. **不扩成系统**：不造排程器、审批器、向量库、后台永久agent；先数据投影+确定性HTML。

以上是主控独立压力测试，不代替Opus设计或Kimi复核；最终取舍在方案文档登记。
