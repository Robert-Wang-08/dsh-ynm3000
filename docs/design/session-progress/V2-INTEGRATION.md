## 重点：关系随层级缩放，不是只打开子任务

|观察动作|整合稿行为|
|---|---|
|L1总览|P01→P02显示“2条”聚合边；展开能看到原始端点，不代表整个P02等待P01|
|下钻P02|W22/W23各自显示外部边；关系面板保留前置T111/T123，不混入P01其他孩子|
|继续下钻W22到L3|显示准确的T111→T221端点；外部节点仍可定位|
|点击外部端点|跳转到对方真实归属层级，不改任务归属|
|返回原焦点|恢复之前的层级、选择、搜索、重点筛选与视图；会话内另保存树折叠和滚动快照|
|上钻|原始边按当前直属祖先重新聚合，内部边收起计数，不丢原端点|
|切四种视图|同一份数据、焦点和选中任务不变|

顶部有三个演示捷径：**L1聚合边 → 下钻P02看外部前提 → 共享工作引用**。也可以从左树自由定位。

新增的 `T111→T221`、`T123→T232` 与 `W21 references T111` 是**合成压力案例，不是对实际业务的依赖推断**，已写入数据meta和页面说明；原样例本身没有跨目标边。共享工作只保留T111一个canonical节点；W21是引用入口，不增加子任务、阻塞或验收计数。

## 收紧的语义

1. **归属树、硬依赖、验收要求三者分开。** 地铁轨道邻接不自动产生依赖；关卡汇合也不表示孩子之间串行。
2. **stage不是验收百分比。** 只有 `acceptance.requires` 明确列出的直属孩子汇入门；没有配置就不造门。本稿只支持直接孩子的门要求，跨目标/跨层requires导入会拒绝。
3. **父目标独立验收。** 子项done、自报完成、旧版本证据都不自动关闭父目标；accepted须绑定human/tool来源、适用版本与证据。
4. **筛选不改事实。** 全层阻塞与后代阻塞标记不因搜索降低；隐藏的依赖仍有计数及端点清单。父子阻塞标记分别列出，不伪称为去重后的事故数。
5. **聚合环不等于原图环。** 原始硬依赖成环拒绝导入；原图无环但上钻出现分组双向关系，保留边并提示，允许下钻查端点。
6. **导入失败不损坏现场。** 校验重复ID、类型、枚举、阶段、缺失关系、共享引用和真实硬环；提交后若渲染异常，也恢复数据、索引和导航缓存。

## 与session-summary/插件的整合边界

这份样例现在可以作为M6的**确定性视图模板**。后续由summary产出的快照通过小适配器映射到本稿的projects/children、dependsOn、references、acceptance；普通会话总结不加载图形规则。真实taskboard卡若作为来源，必须保留卡ID/版本与用户验收权，只读展示，不能让此HTML直接改任务卡状态。

本稿“任务看板”页是演示快照，不是本机dsh-taskboard实时看板；右侧也不是已接入会话log。主动更新仍优先主控在阶段边界更新原事实源，再重建快照；monitor仍为按需二期。
