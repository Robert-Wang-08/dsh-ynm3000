# 常驻工作「DSH 收口备份」

> 版本 **v1.3.0** · 建于 2026-11-03 · 最后修订 2026-11-09 · 入口为工作区根目录的 `dsh-commit-backup.ps1`（备份侧）与 `dsh-restore.ps1`（恢复侧）
> 适用：本工作区（根仓库 + 全部已登记的 git 子仓库）与换机恢复。

## 0. 常驻工作：一句话触发

| 项 | 内容 |
| --- | --- |
| 名字 | **DSH 收口备份**（英文 id `dsh-settle-backup`；恢复侧叫 **DSH 一键恢复**） |
| 一句话 | 「做一次 DSH 收口备份」「收口备份」「备份 DSH」→ 执行第 2 节的备份命令 |
| 一键备份 | `pwsh -NoProfile -File .\dsh-commit-backup.ps1 -Push -Message "chore: 收口备份"` |
| 一键恢复 | `pwsh -NoProfile -File .\dsh-restore.ps1 -Snapshot <bundle> -Apply -AllowPartial`（默认只出计划） |
| 何时做 | 改完 profile 配置/插件清单、升级 config-pack 或 failover、达到一个验证通过的稳定状态、换机前 |
| 完成判据 | 命令退出码 0 **且** 回执 `.ptc\reports\commit-backup-<UTC>.json` 里 `backup.status = ok`（bundle.json 可读、`failed=0`）。只看到一行「备份完成」不算完成 |

口径：**收口** = 把各仓库未提交改动按显式路径提交（不碰凭据/临时产物）；**备份** = 全部 profile 打成
一份可跨机恢复的 bundle。两者都做完才叫「收口备份」——只提交不备份，换机时配置带不走；只备份不提交，
代码改动带不走。

## 1. 它解决什么

本工作区的提交是散的：根仓库 `dsh` 加 7 个子仓库（`dsh-config-pack`、`dsh-provider-failover`、
`dsh-plugin-provider-badge`、`dsh-wechat-hitl`、`dsh-archived-sessions`、
`dsh-plugin-sidebar-visibility`、`dsh-permission-compat`），逐个 `git status` / `git add` /
`git commit` 既慢又容易漏，而且根仓库提交必须等子模块指针落定之后。同时改 profile 配置前要先备份。

脚本把四步合成一条命令：**盘点 → 备份 → 提交 → 可选推送**。备份默认是**全 profile bundle**
（v1.3.0 起），因此同一条命令的产物可以直接在另一台机器上恢复。

## 2. 命令

```powershell
# 1) 只盘点：不动任何文件，先看清楚有什么要提交、什么被排除、哪个仓库被阻塞
pwsh -NoProfile -File .\dsh-commit-backup.ps1 -Status

# 2) 收口备份（一句话触发的就是这一条）：全 profile 快照 + 提交 + 推送
pwsh -NoProfile -File .\dsh-commit-backup.ps1 -Push -Message "chore: 收口备份"

# 3) 备份 + 提交，不推送（本机留档，换机不可用）
pwsh -NoProfile -File .\dsh-commit-backup.ps1 -Message "chore: 收口"

# 4) 只要当前 profile 的旧式单 profile 快照（不能跨机整机恢复）
pwsh -NoProfile -File .\dsh-commit-backup.ps1 -SingleProfile -Message "chore: 收口"
```

备份与恢复也可以单独跑（配置包内入口，不依赖本机 skill 是否装过）：

```powershell
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 backup -AllProfiles
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 restore -AllProfiles -Snapshot <bundle>
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 restore -AllProfiles -Snapshot <bundle> -Apply -AllowPartial
```

`restore` 不加 `-Apply` 只打印计划。`-Apply` 会先逐 profile 写 `pre-restore-<时间戳>`，再按快照写回。
未加 `-Rehearse` 的备份是 partial，写回必须加 `-AllowPartial`。写回后重启 DSH 并新开会话。

### 一键恢复（同机回滚 / 换机恢复）

```powershell
pwsh -NoProfile -File .\dsh-restore.ps1 -List          # 看本机有哪些 bundle
pwsh -NoProfile -File .\dsh-restore.ps1                # 取最新 bundle，只出计划
pwsh -NoProfile -File .\dsh-restore.ps1 -Snapshot <bundle> -Apply -AllowPartial
```

`dsh-restore.ps1` 只做三件配置包入口没有的事：自动定位最新 bundle；写回前检查快照里
`link:` 依赖指向的目录在本机是否存在（换机时路径不一致会在这里暴露）；写回后打印重启与验收步骤。
真正的 verify → pre-restore → 写回仍由配置包入口执行，不重复实现。

### 多 profile 一条命令（v0.11.7 起，v1.3.0 起成为默认）

单 profile 入口一次只处理一个 profile（`-Profile`，默认 `web`）。要把本机**全部** profile
（`web`、`superagent`、`plugtest`、`sa-local`、`web-restore`、`acp`、`headless`、`focushub-dev`、`packed`）
一起打包/一起还原，用 `-AllProfiles`：

```powershell
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 backup -AllProfiles
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 restore -AllProfiles -Snapshot "<bundle 目录>"
pwsh -NoProfile -File .\dsh-config-pack\scripts\dsh-backup.ps1 restore -AllProfiles -Snapshot "<bundle 目录>" -Apply -AllowPartial
```

约定（2026-11-06 拍板）：

| 项 | 行为 |
| --- | --- |
| bundle 布局 | `dsh-backup-<时间戳>\profiles\<profile>\` 下每个 profile 一份标准 `dsh-snapshot/v1`；根目录 `bundle.json`（`schema=dsh-backup-bundle/v1`）记 `default_profile` 与逐 profile 状态 |
| 默认 profile | **不变，仍是 `web`**。bundle 不写任何"默认 profile 指针"，也不改启动命令；恢复后照旧 `dsh web` 启动 |
| profile 范围 | `%USERPROFILE%\.dsh\profiles` 下带 `package.json` 的目录（`node_modules` 之类自动排除）；备份时可用 `-Profiles web,plugtest` 只处理指定几个 |
| 写回顺序 | 先 `verify` 每个子快照的文件完整性，再逐 profile 写 `pre-restore`，最后逐个写回；任一 profile 失败即停 |
| partial | 任一 profile 是 partial 且未加 `-AllowPartial`，`-Apply` 直接拒绝（先看计划） |
| 兼容 | 子目录仍是单 profile 快照，`restore -Snapshot <bundle>\profiles\<profile>` 的老入口照旧可用；单 profile 快照不认 `-AllProfiles`（缺 `bundle.json` 会明确报错） |
| 跨设备前提 | `link:` 依赖仍指向本机检出路径，目标设备必须有同路径仓库克隆（或改 profile 里的 link 目标）；`file:` 本地产物随快照带走 |

> **两套入口的参数名不同**（2026-11-05 复核）：配置包入口用 `-Profile` / `-Snapshot`；skill 入口
> （`~/.agents/skills/dsh-backup-restore/scripts/dsh-backup.ps1`）用 `-ProfileName` / `-From`，并且它的
> `backup -DryRun` 是真的只打印（配置包入口的 `-DryRun` 不会跳过建快照目录）。两者都只处理 snapshot/v1；
> 只有配置包入口有 `-AllProfiles`（skill 入口只能单 profile，多 profile 请用配置包入口）。
> `dsh-commit-backup.ps1` 的 `Resolve-BackupScript` 自 v1.1.1 起优先用配置包入口（自带 `snapshot.mjs`），
> 找不到才退回 skill 入口。本机 web profile 未把 `dsh-config-pack` 装成依赖，skill 入口按
> `profiles/web/node_modules` 找 `snapshot.mjs` 必然失败，这正是旧顺序下「备份静默失败」的原因。

### 参数

| 参数 | 作用 |
| --- | --- |
| `-Status` / `-DryRun` | 只盘点，不备份、不暂存、不提交、不推送 |
| `-Message <文本>` | 提交信息主干。多仓库有改动时自动追加 ` [<仓库名>]`；省略则生成 `chore(auto): 一键提交 <仓库>（N 个文件）` |
| `-Push` | 提交后把各仓库当前分支推到 `origin`（有上游且非分叉时）。**换机恢复必须加**，不加等于只在本机留档 |
| `-NoBackup` | 跳过提交前的 DSH 配置备份 |
| `-SingleProfile` | 只备份当前 profile（旧行为）。默认全 profile bundle |
| `-IncludeUntracked` | 把未被 `.gitignore` 忽略的未跟踪文件一并提交（仍过滤凭据与临时产物） |
| `-IncludeFocusHub` | 把 `focus-hub`（独立应用仓库，根仓库 `.gitignore` 已排除）纳入范围 |
| `-RepairDetached` | 子仓库处于游离 HEAD 时自动切回 `origin/HEAD` 分支 |
| `-Only <名字,...>` | 只处理指定仓库 |
| `-BackupDest <目录>` | 透传给 `dsh-backup.ps1` 的 `-Dest`（跨机时可直接备份到共享盘/移动盘，用户目录之外需 `-AllowPrivateToDest`） |
| `-BackupScript <路径>` | 显式指定 `dsh-backup.ps1`；默认顺序：`$env:DSH_BACKUP_SCRIPT` → 本仓库 `dsh-config-pack\scripts\dsh-backup.ps1`（v1.1.1 起优先）→ 已安装的 skill 入口 |

## 3. 执行顺序与安全规则

1. **发现仓库**：脚本所在目录（根仓库）+ 其下所有含 `.git` 的子目录；排除
   `node_modules` / `attachments` / `downloads` / `claude-mem-lab` / `model-benchmark`，
   默认排除 `focus-hub`（独立应用仓库，需 `-IncludeFocusHub` 显式纳入）。
2. **顺序**：先子仓库（按名字排序），**根仓库永远最后**。注意暂存清单是**提交前一次性扫描**得出的：
   若子仓库的新提交是在本次运行里才产生，根仓库这次的暂存集合里还没有新的子模块指针，
   指针会留成根仓库的一条未提交改动——**再跑一次**即可收口。2026-11-05 实测：同一次运行提交了
   子仓库 3 个文件、根仓库 4 个文件，`dsh-config-pack` 指针需要第二次运行才落进根提交。
3. **备份**：默认在提交前跑一次 `dsh-backup.ps1 backup -AllProfiles`，产出 `bundle.json` 后由脚本
   复核（profile 数、默认 profile、异常项、`failed` 计数），复核结果写进回执。失败只警告不阻断，
   但回执里是 `failed` / `partial` / `unverified`，不会伪装成 ok。
4. **暂存**：只按 `git status --porcelain` 解析出的**显式路径**暂存，通过
   `git add --pathspec-from-file=-` 传入，**从不执行 `git add .` / `git add -A`**。
5. **提交**：见上表；提交正文自动带上脚本版本、UTC 时间戳与备份状态。
6. **推送**：只在 `-Push` 时做，逐仓库检测上游与领先数，**从不 force push、不改写历史**。
7. **回执**：写 `.ptc\reports\commit-backup-<UTC>.json`（`.ptc/` 已被 `.gitignore` 排除），
   含逐仓库盘点、已排除路径、备份 bundle 与 profile 数、失败计数。

### 排除规则（永不提交）

| 类别 | 模式 |
| --- | --- |
| 凭据 / 敏感 | `.credentials.yaml`、`*.credentials.yaml`、`.env`、`.env.*`、`*.pem`、`*.key`、`*.pfx`、`id_rsa*`、`*secret*.json` |
| 本机临时产物 | `.ptc/`、`node_modules/`、`__pycache__/`、`*.bak`、`*.bak-*`、`*.log`、`*.tmp`、`.tmp-*`、`downloads/`、`.wip-backup-*` |
| 未跟踪 | 默认排除；加 `-IncludeUntracked` 才纳入（仍先过上面两条） |

被排除的项会逐条打印原因，不会静默丢弃。

### 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功（或只盘点） |
| 1 | 有仓库提交/推送失败 |
| 2 | 有仓库被阻塞（游离 HEAD、非 git 仓库） |

### 真实执行记录（2026-11-03 12:55 本地时间）

首次真实运行又暴露三个只在真机才出现的缺陷，都已修掉并复测：

| 缺陷 | 现象 | 修法 |
| --- | --- | --- |
| 修游离 HEAD 时改集合 | `Collection was modified; enumeration operation may not execute`，脚本在提交前中断 | 先收集要刷新的仓库名，遍历结束后再按下标重建状态 |
| 暂存后统计文件数 | 每次提交都报"1 个文件"（`Get-GitLine` 返回的是 join 过的单个字符串，`Measure-Object` 恒为 1） | 直接取 `$s.Stage.Count` |
| `core.quotepath` 默认转义 | 中文路径被转成 `\344\270\200…`，`git add` 报 `pathspec ... did not match any files` | `git -c core.quotepath=false status` + 去引号/反转义 |
| 子模块"内容脏"误判 | 子模块只有工作区改动（` m`/` ?`）时也会被当成待暂存项，拿去 commit 会因空改动失败 | `git status --ignore-submodules=dirty`：指针真移动（` M`）才处理 |
| `-RepairDetached` 可能覆盖本地分支 | 原实现直接 `checkout -B <分支> origin/<分支>`：若本地分支上有云端未含的提交，会被硬挪走，只能靠 reflog 找回（`dsh-plugin-provider-badge` 那次恰好是纯落后，才没丢东西） | 先算 `origin/<分支>..refs/heads/<分支>`：**>0 直接拒绝并报错**；为 0（纯快进）或分支不存在时才 `-B` |

## 5. 跨机一键恢复（v1.3.0）

### 源设备（收口备份）

```powershell
pwsh -NoProfile -File D:\src\dsh\dsh-commit-backup.ps1 -Push -Message "chore: 收口备份"
# 产物：%USERPROFILE%\.dsh\backups\dsh-backup-<时间戳>（含 bundle.json 与 profiles\<profile>\）
```

### 目标设备

```powershell
# 1) 克隆仓库群到与源设备一致（或已知）的路径
git clone --recurse-submodules https://github.com/Robert-Wang-08/dsh-ynm3000.git D:\src\dsh

# 2) 把源设备的 dsh-backup-<时间戳> 目录拷到目标机（共享盘/移动盘均可）
```

## 6. 已知限制

- **`dsh-config-pack` 与云端分叉（2026-11-05 已收敛）**：2026-11-03 记录过的分叉已不存在。
  2026-11-05 复核：根仓库 + 7 个子仓库共 8 个仓库，本地 HEAD 与 `origin` 同名分支的远端 SHA 全部一致
  （无落后、无领先、无分叉）。脚本仍然**不会**自动合并分叉：真遇到分叉它只警告"本地与云端分叉"，
  集成必须人工做。
- **游离 HEAD**（`dsh-plugin-provider-badge`）：脚本默认只阻塞并报告；加 `-RepairDetached`
  才会 `git checkout -B <origin/HEAD 分支>`。若提交前不切分支，提交会挂在游离 HEAD 上、随后可能丢失。
- **`focus-hub`** 是独立应用仓库、根仓库 `.gitignore` 已排除，默认不处理。2026-11-05 复核：
  它**已有** `origin`（`https://github.com/Robert-Wang-08/focus-hub.git`），本地 `main` 领先 76 个提交
  且工作区有未提交改动，但仍未注册为 submodule；需要把它纳入某次提交时显式加 `-IncludeFocusHub`。
- **跨机恢复是 partial**：默认备份不请求 `-Rehearse`（隔离安装演练），`bundle.json` 里每个 profile 是
  `partial`。这表示文件与摘要可校验，但**没有演练过重装依赖**；写回必须 `-AllowPartial`，
  恢复后按装机引导跑 `pnpm install` 与 `verify-install` 才算验收。
- **`link:` 路径是换机最大坑**：profile 依赖里 `link:D:\src\dsh\...` 指向源设备路径。目标机克隆路径必须
  一致，否则恢复出来的 profile 会指向不存在的目录。`dsh-restore.ps1` 会体检并列出缺失项。
- **凭据不随备份走**：`.credentials.yaml`、API key 原值、会话、附件、日志、`node_modules` 都不在快照里；
  换机后仍需按装机引导重新配置密钥。
- **DSH 沙箱**：文件策略为只读、或工作区 `workspace-write` 但 `.git` 子目录不可写时，git 写操作会
  报 `Permission denied`。这不是脚本缺陷，请在本机终端（沙箱外）运行。本机 2026-11-03 的实测：
  `danger-full-access` 策略下可正常读写 `.git`。
  2026-11-05 在 `workspace-write` 下复核，越界的**不只有** `.git`：

  | 动作 | 现象 | 沙箱内可用替代 |
  | --- | --- | --- |
  | `git fetch` | `error: cannot open '.git/FETCH_HEAD': Permission denied`（同一工作区其他路径可写，只有 `.git` 被拒） | `git ls-remote origin <branch>` 只读不写：能判断"是否落后/领先"，拿不到计数 |
  | `dsh-backup.ps1 backup -DryRun` | 仍先 `mkdir %USERPROFILE%\.dsh\backups\dsh-backup-<时间戳>\files` → `EPERM`（`-DryRun` 只跳过写回，不跳过建目录） | 只能查快照目录是否已存在、最新快照时间；不能替代真正的备份 |
  | `engine-preflight.ps1` | 判决要写 `<DSH_HOME>\device\engine-preflight.json` → `Permission denied`，退出码 1 | 恢复门槛读该文件；已有 `in-sync` 旧判决时不阻断，但不能声称"刚做过预检" |

  三项在 `danger-full-access` 下均正常；沙箱内得出的结论必须注明"未提权，未执行"。
- 脚本不负责 profile 的 `pnpm install` / 插件重装；恢复流程仍走 `dsh-backup-restore` 的恢复命令。

## 7. 回滚

脚本不做破坏性操作，回滚即按 git 语义还原：

```powershell
# 撤销最近一次提交但保留改动
git -C D:\src\dsh reset --soft HEAD~1
# 撤销暂存（未提交时）
git -C D:\src\dsh reset
# 已推送的提交：不 force，改用新提交修正
```

配置备份在 `%USERPROFILE%\.dsh\backups\dsh-backup-<时间戳>\`。恢复先跑
`dsh-restore.ps1 -Snapshot <该目录>` 看计划；确认后加 `-Apply -AllowPartial`。
`-Apply` 会先逐 profile 写 `pre-restore-<时间戳>`。
